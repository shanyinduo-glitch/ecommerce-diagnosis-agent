# 八人分工与两周排期

成员姓名尚未提供，暂以 A–H 标识。每人都有独立可验收交付物；按实际能力可交换角色，但接口和验收责任不变。单 Agent 架构不妨碍八人并行开发。

## 分工与交付物

| 成员 | 主责 | 具体工作 | 必须交付 | 协作与复核 |
|---|---|---|---|---|
| A | 项目负责人、架构与集成 | 控制范围；维护 schemas、配置、CLI；组织合并和端到端联调；复现说明 | 可运行入口、接口文档、依赖配置、README、集成检查记录 | 与所有人协调；H 复核复现流程 |
| B | Qwen 接入与 Agent 决策 | API 调用、工具定义、提示词、状态循环、动态计划、终止和重试策略 | llm_client、controller、prompts、state；真实多轮轨迹 | F 对接执行反馈；E 复核推理是否有证据 |
| C | 数据检查与清洗 | 类型/字段/主键检查；重复识别；冲突隔离；缺失商品关联；质量影响 | inspect_data、cleaning、质量报告、清洗测试 | D 消费干净数据；E 复核处理口径 |
| D | 指标计算与拆解 | 两期指标；渠道/品类变化及贡献；每日汇总；渠道访客与可选转化分析 | metrics、breakdown、标准 CSV/JSON、指标测试 | C 提供输入；E 独立复算；G 使用输出 |
| E | 分析校验与证据审查 | 验证金额守恒、连接基数、零分母、贡献符号；审查无依据结论；验证恢复后的结果 | checks、核对测试、证据审查记录、边界样例 | 不直接照抄 D 算法作测试；复核 C/D/B |
| F | Python 执行工具与运行记录 | 执行环境、超时、错误结构、产物索引、工具日志；汇总调用与运行耗时 | python_runner、artifacts、trace、usage、错误反馈样例 | B 提供 API Token 信息；A 负责部署集成 |
| G | 图表与分析报告 | 每日趋势、分组变化图；指标表；报告模板；结论证据引用和展示可读性 | charts、report、三案例报告、至少两图/案例 | D/E 确认数值；H 汇总进最终课程报告 |
| H | 评测与课程交付 | 评分脚本、批量运行、恢复评测；整理性能、失败案例、课程报告与展示 | evaluation、评测表、最终报告、展示提纲、演示脚本 | E 复核评分；A 确认完整复现；全员提供各自内容 |

H 负责整合文稿，不负责代写所有成员的工作。每人提交自己的方法、结果、截图或日志证据、局限性和贡献说明。

## 关键交接

1. A 第 2 天前冻结配置、结果字段与工具错误结构，避免八人分别定义相同字段。
2. C 向 D/E 交付干净明细、隔离记录、质量计数及金额影响。
3. D 向 E/G 交付机器可读指标，不用聊天复制数字作为正式接口。
4. F 与 B 用相同工具协议对接，先跑一个最小计算，再加入真实异常反馈。
5. E 验证后由 G 生成报告；失败校验写入状态，不能静默略过。
6. H 在独立评测侧读取参考答案；B 的 Agent 不可读取答案或场景映射。
7. A 将各模块接入同一 CLI，并在新环境按 README 完整复现。

## 两周排期

| 时间 | 主要工作 | 里程碑与责任 |
|---|---|---|
| 第 1 天 | 全员读要求；确认角色、Qwen 权限、范围；建立仓库规范 | A 输出需求清单；所有人确认指标口径 |
| 第 2 天 | 冻结接口与目录；准备工具和报告样例 | A 交付 schemas；B/F 完成最小调用链；C 提供数据检查 |
| 第 3–4 天 | 并行完成清洗、指标、执行工具和 Agent 初版；E/H 建验证样例；G 做图表模板 | C/D/F 模块可单测，B 能完成工具调用 |
| 第 5 天 | 接入 case_01，打通检查→计算→反馈→报告 | A 主导第一条端到端链路，输出真实轨迹和报告 |
| 第 6–7 天 | 跑通三个公开案例，修正口径与报告 | E/H 核对数值；G 完成三份报告；第一次功能验收 |
| 第 8–9 天 | 重点验证代码报错恢复、缺字段、异常关联；完善日志 | B/F/E 提交恢复证据；不可计算场景能诚实降级 |
| 第 10 天 | 正式批量评测，记录调用、Token、耗时和失败 | H 输出评测初稿；全员分析失败和成本 |
| 第 11 天 | 修复实质问题；补充额外种子或无下降场景 | A/E 验收；冻结功能，P1 来不及则不做 |
| 第 12 天 | 整理课程报告、成员贡献、展示稿与演示数据 | H 整合；每人提交自己的方法与证据 |
| 第 13 天 | 新环境复现；约 10 分钟完整彩排 | A/H 执行；准备录屏或已完成结果作为演示备份 |
| 第 14 天 | 检查附件、密钥、命令和交付完整性；提交 | 全员最终签核，保留提交版本 |

## 协作约定

- 每人围绕自己模块提交小批变更，修改共享 schemas 先与 A 对齐。
- 每天短同步：已完成、阻塞、下一交接物；不要靠长会议代替接口交付。
- 计算代码与公开答案核对，Agent 则用真实工具反馈验收，二者缺一不可。
- 功能完成标准：可运行、有必要验证、有产物、有使用说明，不能只交设计文字。
- 第 5 天若完整链路仍未跑通，立即减少可选界面和扩展功能，优先保证 P0。

## 展示分工建议

10 分钟不必让八人平均讲。建议 A 讲目标与架构 1 分钟；C/D 讲数据和分析 2 分钟；B/F 现场展示 Agent 与错误恢复 3 分钟；E/H 讲评测和局限 2 分钟；G 展示证据报告及团队反思 2 分钟。可由少数主讲人串联，全员参与材料准备和答疑，最终依教师要求调整。
