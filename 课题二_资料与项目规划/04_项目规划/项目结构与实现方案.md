# 项目结构与实现方案

目标是在两周内实现一个可复现、能核查证据、能够根据工具反馈调整步骤的单 Agent。以下是建议方案；此目录仅交付规划，没有创建应用代码。

## 技术范围

建议 Python 3.10+，Qwen API，pandas 处理数据，matplotlib 绘图，pytest 验证关键计算与恢复行为。先做 CLI 入口，报告采用 Markdown、CSV 和 PNG。具体 Qwen 模型及 SDK 在接入阶段根据实际账号和官方接口确认。

第一版不做数据库服务、向量检索、多 Agent、模型训练和复杂前端。Python 执行能力满足课题最低要求，不必同时实现 SQL。核心完成后，有余力再加轻量展示页面。

## 运行流程

用户指定案例目录和两个时期 → Agent 检查文件与字段 → 制定简短计划 → 选择工具或生成 Python 分析代码 → 读取结果及报错 → 必要时修正和重试 → 校验指标及拆解 → 生成证据表和图 → 输出报告与运行日志。

确定的口径与校验规则可以写成稳定函数；数据观察、分析顺序、进一步下钻和异常恢复由模型决定。设置最大步数、执行超时和预算，达到限制后返回已完成结果与未解决问题，不能伪报成功。

## 模块接口约定

| 接口 | 输入 | 输出 | 负责人 |
|---|---|---|---|
| inspect_data | case_dir、检查项 | 表结构、样本、日期范围、质量提示 | C |
| clean_data | 三张表、清洗规则 | 干净明细、冲突隔离表、质量报告 | C |
| compute_metrics | 干净明细、流量、两期边界、分组维度 | 结构化指标及表文件 | D |
| validate_results | 总体、分组、质量结果 | 校验状态、差额、异常明细 | E |
| execute_python | 代码、输入文件映射、工作目录、超时 | stdout、stderr、退出码、产物路径 | F |
| run_agent | 案例、时期、模型配置 | 最终状态、指标与产物索引 | B |
| build_report | 指标、质量结果、证据索引 | 报告和图表路径 | G |
| evaluate_run | 运行产物、独立参考答案 | 得分、误差明细、性能数据 | H |

A 负责冻结接口与集成，所有接口共用 schemas。建议工具返回统一包含 `ok`、`data`、`artifacts`、`error`；错误包含类型、信息与是否可重试。金额使用精确值计算，JSON 明确单位；不可计算值用 null 并附原因。

## 必须实现的内容与验收

| 阶段 | 实现内容 | 完成标准 |
|---|---|---|
| P0 数据基础 | 读取、清洗、隔离、商品关联、流量关联 | 三组质量计数一致，金额可追溯 |
| P0 分析计算 | 总体、渠道、品类、日趋势和核心指标 | 与公开答案核对，差额守恒 |
| P0 Agent | Qwen 工具调用、多轮反馈、终止条件 | trace 展示模型依据结果调整后续动作 |
| P0 错误恢复 | 执行报错反馈、模型修正、重新执行 | 可展示一次真实失败到修复的完整过程 |
| P0 报告 | 证据表、至少两图、结论与边界 | 结论可定位到计算产物，图有单位和时期 |
| P0 评测 | 三案例正确率、识别率、用量和耗时 | 生成机器可读结果与汇总表 |
| P1 泛化 | 额外种子、缺字段、无下降场景 | 不依赖案例编号，不伪造缺失指标 |
| P1 展示 | 可选页面或更好的报告排版 | 不影响 P0 截止交付 |

## 执行边界与可复现性

执行工具只挂载指定案例和当次输出目录；参考答案、生成脚本、API 密钥不进入代码执行环境。建议子进程设置超时、输出大小上限和独立工作目录；这些限制不等同于安全沙箱，需要部署时用容器或操作系统权限落实文件和网络隔离。

凭证只供调用模型的主进程使用，不写入提示词、日志或仓库。记录输入文件哈希、模型名、采样参数、提示词版本、代码版本和运行时间。保留实际 API 返回的 Token；取不到时标记缺失，不把估算记成真实计量。
