共同要求：每组 6–8 人，周期两周，使用 Qwen API，不要求训练或微调。命令行、Notebook 或阿里云百炼应用均可。

题目二：电商销售下降分析 Agent
任务目标
假设你们是一家电商公司的数据分析团队。负责人提出：“最近两周销售额下降了，请找出主要下降来源，并检查是否存在数据质量问题。”
每组需要开发一个 Agent，让它自主检查数据、选择分析步骤、执行 Python 或 SQL、读取结果或报错，并根据反馈继续分析，最终生成一份有计算证据的报告。
本题的“下降原因”限定为数据能够支持的指标变化与下降来源。例如可以报告“渠道 A 的销售额减少，占总减少额的 70%”，不能仅凭这些数据断言“竞争对手促销导致下降”。
数据生成与领取
本题使用课程脚本生成的模拟数据，不依赖外部网站。附件提供 generate_ecommerce_data.py 和已经生成好的 ecommerce_public_3_cases.zip。学生可以直接解压公开数据，也可以运行脚本重新生成同一批数据：
python3 generate_ecommerce_data.py --mode public --output data/ecommerce_public --seed 20261018
公开模式生成 case_01、case_02、case_03 三个目录和 public_reference_answers.json。三个公开案例分别设置渠道流量下降、品类退款上升和品类客单价下降；参考答案用于检查数据处理和指标计算，不限制 Agent 的分析步骤。
脚本先生成 60 个商品，覆盖数码、家居、服饰、美妆和食品；再生成 2026-09-01 至 2026-09-28 的渠道访客、订单及订单明细。订单量由访客数和渠道转化率抽样得到，商品价格、数量、优惠和退款按固定随机种子生成。每组数据再加入 12 个完全重复明细编号、4 个字段冲突明细编号和 8 条无法匹配商品表的记录。相同命令和种子会得到相同数据。
数据与口径
每组数据约 1 万条订单明细，包含三个文件。
文件
主要字段
order_items.csv
订单编号、明细编号、日期、商品编号、渠道、数量、原价金额、优惠金额、退款金额
products.csv
商品编号、商品名称、品类、商品标价
traffic.csv
日期、渠道、访客数

前 14 天为对比期，后 14 天为分析期。金额单位统一为元，原价、优惠和退款金额均为整条订单明细的金额，无须再乘数量。退款统一归属于原订单日期，不要求分析退款发生时间。
净销售额＝原价金额－优惠金额－退款金额。订单量＝去重后的订单编号数。客单价＝净销售额÷订单量。退款率＝退款金额÷（原价金额－优惠金额）。分母为零时标记为不可计算，不用零代替。跨天汇总访客数表示访客人次，不表示跨天去重人数。
数据包规定每个订单只属于一个渠道；每条明细对应一个商品；商品编号在商品表中唯一，流量表的“日期＋渠道”组合唯一。完全重复的明细按明细编号去重；同一明细编号字段冲突时，隔离该编号的全部记录，不计入清洗后的指标，并单独报告排除金额。无法匹配商品信息的明细保留金额，品类标记为“未知”。关联流量与订单时，应先按日期、渠道汇总订单，避免按订单明细连接后重复计算访客数。
数据中会设置可核查的下降来源，例如某渠道流量减少、某品类退款增加或客单价下降，并加入重复明细、商品关联缺失等数据质量问题。
Agent 必须完成的分析
报告需要给出两个时期的净销售额、差额和变化率；按渠道、品类分别拆解销售额变化，定位主要减少来源；比较订单量、客单价、退款率及渠道访客变化；说明数据质量问题及其处理前后影响。
按渠道或按品类拆解时，各分组差额之和应等于总差额。下降贡献＝分组销售额减少额÷总销售额减少额；增长分组的贡献为负，个别下降分组的贡献也可能超过 100%。渠道与品类是两种拆解视角，不能把两者的贡献相加。总销售额没有下降时，应明确报告没有下降，不强行给出下降归因。
结论必须对应实际计算结果，并附关键表格及至少两张图。建议包含每日净销售额趋势图，以及渠道或品类销售额变化图。图中应标明时间、单位和比较对象。
Agent 的最低能力
至少接入数据检查工具和 Python 或 SQL 执行工具。Qwen 必须根据工具返回结果决定下一步动作，不能把全部分析步骤固定写死。
系统应保存简短计划、每一步工具输入与输出、错误信息、修改动作、最终结论和证据文件。代码报错后能够修改并重试；字段缺失或关联结果异常时能够检查数据并调整方案。
必须完成的实验
在 3 组公开数据上报告关键数值正确率、主要下降来源识别率、调用次数、Token 用量和耗时。涵盖Agent分析过程的分析。
