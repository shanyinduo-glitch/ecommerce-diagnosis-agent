## 真实错误恢复

故障注入运行：`outputs/runs/case_01/20261106_204319_1cb9d2/`。

首次 SQL 被测试装置明确替换为 `SELECT injected_missing_column FROM items LIMIT 1`，数据库返回不存在字段错误。模型收到实际错误后重新提交有效查询，成功完成分析并生成报告。requested_query、executed_query、注入标志保存在 sql_attempts.jsonl，原错和新查询分别保存，不能把此受控错误称为模型自然产生的代码错误。

该运行 completed，数值 66/66，14 次模型请求、14 次工具调用、89,378 Token、61.375 秒。另一次任务 ID 重复错误也通过修改计划恢复。

正常运行中也出现过复用已完成任务 ID 的工具拒绝（case_01 两次，case_02 一次，case_03 一次），模型通过新增任务和修改计划继续执行，均保留在 errors.json 与 trace.jsonl；没有将这些错误从统计中抹去。

## 第一版边界和后续优先级

1. 当前无容器环境，因此使用受限内存 SQL 执行生成代码；注册 Python 工具负责计算。没有开放任意 Python 沙箱，满足课程的 Python 或 SQL 执行要求。
2. 模型解释仍需语义复核。例如 case_02 将退款与净客单价变化并列解释，二者存在口径重叠；报告已明确不能作为独立损失相加。case_03 提到“高价值服饰成交减少”，目前证据首先支持客单价下降，若要确认价格/结构机制还需更细分解。模型提出的政策、物流、质量问题都不能当作已确认根因。
3. 关键字段缺失时会保留检查结果并报告 partial，尚未实现对所有可用指标的细粒度降级计算。
4. 有状态快照但无自动断点续跑；没有 Web 界面、CausaLens 联调或正式课程 PPT。
5. 正常案例目前各一次，后续应重复运行验证稳定性，并压缩历史工具结果降低 Token。当前完整轨迹优先，Token 用量较高。
6. 课程总报告与展示材料可以基于现有真实结果制作，本次交付的是第一版 Agent 和验证材料。

数据传输核验：首次网络审批因疑似敏感业务指标被拒，随后离线重新运行课程随机生成脚本，确认全部九张 CSV SHA256 一致，证明其为公开模拟数据后审批通过。没有上传旧项目数据。部分请求审批服务超时后重试成功，不影响上述真实运行结果。
