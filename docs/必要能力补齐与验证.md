# 必要能力补齐与验证

更新日期：2026-11-13。本文记录首版之后的实现补齐，不是课程总报告。课程报告和 PPT、Web 界面、任意 Python 沙箱及 CausaLens 联调不在本轮范围。

## 已补齐的能力

### 结论检查与解释边界

新运行的 finish 接口只接受三种结构化事实：两期指标比较、最大下降渠道或品类、退款账面桥接。模型选择结论类型、对象与证据；程序核对可用性、排名、贡献和金额关系，从指标生成文字并保存 metric_paths。

校验失败会返回工具错误，模型可以修正参数或补充分析。结论必须覆盖总体变化，以及总体下降时两个可用的分组视角。禁止通过 statement 参数提交自由文本；历史模型原文仍保留，报告明确标记为未经语义验证。

这是一种有边界的指标结论检查，不是任意自然语言的语义证明，也不进行业务因果识别。SQL 下钻仍由模型自主选择；支持的结构化结论主要绑定标准指标，不能把 SQL 引用存在本身当成推理已经获证。

### 指标分解

总体、每个渠道和品类均生成两个独立视角：

- 退款前销售额变化 − 退款金额变化 = 净销售额变化。
- 订单量项 + 净客单价项 = 净销售额变化，使用两因素对称分解，计算阶段不提前舍入。

净客单价已经扣除退款，两套分解不能相加。分解是账面恒等式，不代表干预效应或退款的业务原因。零订单或金额不可用时标记不可计算。

### 清洗对下降来源判断的影响

比较含异常的原始行汇总与按课程规则清洗后的总体差额、渠道和品类排名、并列最大下降组及其变化。原始行汇总只用于展示异常影响，不是真实交易基准。来源没有变化仅表示本次已检查清洗前后的一致性，不表示对所有异常普遍稳健。

未知商品继续保留金额并归为未知；商品表整体异常时停用品类分析，不能把无法可靠关联的整表记录都伪装成普通未知商品。

### 细粒度降级

- 缺失、重复键或覆盖不完整的流量：停用访客指标，保留可计算销售指标。
- 商品表缺失、主键冲突、品类不可用：停用品类拆解，保留总体及有效渠道。
- 退款缺失或无效：保留订单数、可计算退款前销售额等，净销售额、净客单价和下降贡献不可用。
- 渠道缺失或同订单跨渠道：停用渠道拆解，保留总体和有效品类。
- 金额字段只要存在无法解析的记录，就停用整个相关指标，不以有效子集冒充全量。
- item_id、order_id 或订单日期无法安全确定：停止安全计算，保留检查结果和 partial。

availability 同时列出可用指标、full 和原因。缺失字段时去重/冲突只能依据现有字段，这个限制也会写入报告。verify.passed 仅指已执行检查通过；skipped 不视为已验证，full=false 的运行不会变成 completed。

### 检查点续跑

原子保存完整消息、任务、已完成集合、待处理调用、证据及累计用量；从保存的工具边界继续，已提交的任务不重复执行。数据、模型分析配置、源码或证据哈希变化时拒绝续跑；预算参数可以显式追加。进程锁阻止同一目录并发恢复。

中断时在途模型请求结果未知，则原尝试保留在调用次数中，Token 标记不完整；在途受限工具尝试保留计数，并从已保存边界恢复。旧首版审计快照没有完整消息，不支持续跑。不能承诺远端请求恰好执行一次或未知 Token 可恢复。

### 重复实验与图表素材

评测器预先记录所有计划尝试，逐次持久化结果；partial 和失败不丢弃。仅在配置、数据哈希、源码与运行模式一致时合并统计。故障注入、续跑与正常运行分别统计。输出每次运行 CSV、分组 CSV、JSON 与 Markdown，包含完成率、正确率、结论检查、重试恢复、调用、Token、耗时与离散程度。

新完整运行生成七张图：每日趋势、渠道差额、品类差额、退款桥接、订单量—净客单价分解、清洗渠道影响、清洗品类影响。PNG 为 300 dpi，同时保存 SVG、图注、时期、单位和来源哈希。export_figures.py 复制自包含的图表与证据包，不修改原运行。

单案例集成联调：`outputs/evaluations/20261113_151939_affc33/`。case_02 completed，66/66，13 次请求，99,028 Token。一次结构化参数错误被模型修复。该联调没有混入正式重复实验。

| 案例 | 完整完成 | 中途或首次请求受限 | 已完成运行固定数值字段 |
|---|---:|---:|---|
| case_01 | 2/3 | 1/3 | 每次 66/66 |
| case_02 | 1/3 | 2/3 | 66/66 |
| case_03 | 1/3 | 2/3 | 66/66 |

前四次 completed；第五次 case_02 已计算 66/66，但在第 18 次模型请求收到 403，报告未完整结束；后四次首次请求即 403。不能把已计算指标正确当成该次 Agent 完整成功，也不能剔除受限运行后声称稳定性 100%。九次记录总 Token 为 575,781，其中五次请求用量不完整，不能视为完整总消费；联调另计 99,028 Token。

随后仅使用“请回复 OK”的最小请求诊断，模型明确返回 `AllocationQuota.FreeTierOnly`：免费额度耗尽，且账户仅允许免费调用。没有更改账户设置或启用付费。真实重复实验因此只取得初步、受外部额度限制的证据；同一最终版本的完整三次成功重复验证仍待额度恢复。

真实受控暂停续跑、当前版本 SQL 故障恢复实验入口已经准备：`scripts/verify_recovery.py --mode resume` 和 `--mode sql-error`。由于已经确认外部额度限制，未重复发起必然失败的付费接口验证。断点续跑与错误路径已经通过本地测试；当前版本的真实 API 恢复验收仍待补做，不能沿用首版实验冒充。

正式实验源码哈希保存在 protocol.json 和每次 manifest.json。实验后只增加了脱敏的配额错误码说明、修正图表负值标签边距，并完成最终 69 项回归；没有重新运行 API 或把渲染副本当作新稳定性结果。

## 切换 Flash 后的补验结果

以上额度受限记录属于此前的 qwen3.8-27b 阶段，原始记录保留。按用户要求改为 qwen3.8-flash 后，已经完成之前受限的真实验证。默认模型和环境变量示例均已更新。

首次 Flash 尝试暴露一次性任务完成状态反馈不足：数值正确但模型反复复用 SQL 编号。保留三个 partial、一个主动中断和五个未执行项后，补充权威的任务状态、可执行编号、必做证据与剩余预算反馈；没有提高预算、自动重开任务或替模型作出分析决策。

最终冻结版本正常重复实验：`outputs/evaluations/20261113_160313_02440f/`，三个案例各三次，9/9 completed，594/594 固定数值字段通过，两个分组视角各 9/9 命中；108 项结构化指标结论核查通过。81 次模型请求，578,879 Token，用量完整；两个工具错误均恢复，没有复用已完成编号的错误。平均每次 37.708 秒，范围 28.453–61.282 秒。不能将源码不同的历史模型结果作为严格控制变量的性能比较。

当前版本的两项单列真实实验均通过：

- `outputs/recovery/20261113_160958_resume_544b62/`：四次请求后 partial，同目录续跑至 completed。累计 9 次请求、61,159 Token，包括暂停前 11,397 Token；66/66。验证的是受控预算边界恢复，不是所有强制进程中断情形。
- `outputs/recovery/20261113_161001_sql_error_3eedc4/`：真实注入不存在字段错误，模型读取错误并修正 SQL，最终 completed、66/66；13 次请求、110,071 Token。没有把受控注入称为模型自然写错。

新增五项反馈测试后，本地完整回归为 74 项通过（38.59 秒）。新的组员素材包位于 `outputs/teammate_figures/20261113_flash.zip`，含 21 张 PNG、21 张 SVG 和证据。先前素材保留。详细过程和独立核查见 `qwen3.8-flash补验记录.md`。
