# 第一版实现架构

Qwen 通过 `langchain-openai` / `langchain-core` 调用结构化工具；项目没有安装或使用 LangGraph 编排。自定义控制器维护任务列表、依赖、完成集合、证据索引及调用预算。

工具为 update_plan、inspect_data、prepare_data、compute_metrics、run_sql、create_charts、finish。模型必须提交结构化计划，每次调用根据返回值决定后续动作。可以新增下钻任务、修改任务依赖、纠正失败 SQL，必做证据不能通过修改计划跳过。

数据检查、清洗、标准指标与图表由已实现的 Python 函数执行。模型生成的查询在 SQLite 内存数据库运行。只读授权器只允许 items、traffic、daily_channel 三表及受限聚合函数，禁止文件数据库挂载和扩展，查询设指令数、时长、长度与结果行数限制。

这是针对当前无容器环境的首版调整：满足课程“Python 或 SQL 执行工具”的要求，不实现任意 Python 代码沙箱。生成 SQL 以 .sql 保存，报错回传模型修正，恢复实验保留 requested_query 与实际注入故障的 executed_query，不能把注入错误误算为模型自身写错。

finish 检查数据检查、标准指标、至少一次成功 SQL 下钻、三图和计划任务完成。计算器在生成指标后自动执行守恒检查。模型解释通过引用 ID 存在性检查，但没有自动完成逐句语义证明，报告明确区分确定性指标与模型解释。

CLI 通过配置读取模型及时期，默认 max_calls=20、max_tool_calls=30、max_errors=6、max_seconds=600，模型单次请求 timeout=90。总时长在请求之间检查，因此一次已发出的请求可能延长最终结束时间。每次尝试均计入模型调用数，API 未返回用量时计量标记不完整。

状态快照与计划版本支持审计，第一版不承诺自动断点续跑。关键字段和关联契约不满足时返回 partial；仍未实现缺字段条件下所有可用子指标的细粒度降级。

代码在本项目运行，原始课程资料和 CausaLens 不被修改。参考答案仅由独立评分器读取，模型工具没有文件路径参数。
